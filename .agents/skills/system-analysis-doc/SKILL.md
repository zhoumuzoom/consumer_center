# 系统分析文档模板

**身份：系统分析文档标准模板，用于规范技术设计文档的编写格式。**

## 文档结构

系统分析文档应包含以下九个标准章节，按顺序编写：

### 一.项目背景
*没有可不填*

说明项目的业务背景和起因，例如：
- 部门快速增长，业务量本月增长40%
- 现有系统无法满足业务需求
- 新业务场景需要技术支持

### 二.当前现状
*没有可不填*

描述当前系统的现状和痛点，例如：
- 依赖人工手动执行，缺乏自动检测与预警机制
- 系统性能瓶颈
- 数据不一致问题

### 三.开发目标

#### 3-1.业务目标
说明业务层面的目标，例如：
- 流程全自动化，不再依赖人工操作与调度
- 提升用户体验
- 降低运营成本

#### 3-2.技术目标
说明技术层面的目标，例如：
- 引入kafka消息队列
- 新增分布式锁
- 新增xxl-job定时任务
- 优化系统性能

### 四.系统架构图

使用画板（whiteboard）绘制系统架构图，展示：
- 系统模块划分
- 模块间调用关系
- 技术栈选型
- 部署架构

格式：`<whiteboard token="xxx"></whiteboard>`

### 五.业务流程图/时序图

（本次业务改造链路的流程图，或者时序图，二选一即可。对于一些不好出的时序图，画流程图即可）

#### 流程图
使用画板绘制业务流程图，展示业务流转过程。

格式：`<whiteboard token="xxx"></whiteboard>`

#### 时序图
使用画板绘制时序图，展示系统间交互时序。

格式：`<whiteboard token="xxx"></whiteboard>`

#### 泳道图
使用画板绘制泳道图，展示各角色/系统的职责分工。

格式：`<whiteboard token="xxx"></whiteboard>`

### 六.数据库改造

#### 6-1.ER图
使用画板绘制数据库ER图，展示表结构和关联关系。

格式：`<whiteboard token="xxx"></whiteboard>`

#### 6-2.数据库详细设计

为每个新增或修改的表提供详细设计，格式如下：

**表名：xxx_table**

| **字段名** | **类型** | **说明** | **约束** |
|-|-|-|-|
| id | bigint | 主键 | PK, AUTO_INCREMENT |
| field_name | varchar(50) | 字段说明 | UK/NOT NULL 等 |
| create_time | datetime | 创建时间 | NOT NULL |

**设计要点：**
- 字段命名使用下划线分隔
- 必须包含主键、创建时间字段
- 明确标注约束条件（PK、UK、NOT NULL等）
- 字段类型选择合适的MySQL类型

### 七.前后端联调接口

为每个接口提供详细定义，格式如下：

**接口名称：简短描述**

| 接口地址 | /api/xxx/endpoint |
|-|-|
| 请求方法 | GET/POST/PUT/DELETE |

**请求参数**

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|-|-|-|-|-|
| pageNum | Integer | 否 | 1 | 当前页码 |
| pageSize | Integer | 否 | 10 | 每页数量 |
| param_name | String | 否 | - | 参数说明 |

**响应数据**

| 参数名 | 类型 | 说明 |
|-|-|-|
| success | Boolean | 是否成功 |
| code | Integer | 状态码 |
| message | String | 提示信息 |
| data | Object | 数据对象 |

**响应对象**（如data为复杂对象）

| 参数名 | 类型 | 说明 |
|-|-|-|
| field1 | type | 字段说明 |
| field2 | type | 字段说明 |

**接口设计要点：**
- 遵循RESTful风格
- 明确标注必填/选填
- 提供默认值（如有）
- 响应体统一使用Result对象
- 分页接口统一使用pageNum/pageSize

### 八.测试用例

列出核心功能的测试用例，格式如下：

| 用例编号 | 测试场景 | 前置条件 | 测试步骤 | 预期结果 |
|-|-|-|-|-|
| TC001 | 场景描述 | 前置条件 | 1.步骤1<br>2.步骤2 | 预期结果 |

### 九.部署说明

#### 9-1.升级说明
说明部署步骤，按顺序执行，例如：
1. 先执行update.sql（数据库变更）
2. 修改nacos配置（配置变更）
3. 部署jar包（代码部署）

#### 9-2.异常说明
说明回滚方案，按优先级执行，例如：
1. 将nacos配置改为false（关闭新功能）
2. 回退jar包/回退代码（代码回滚）

## 使用指南

### 创建新文档
当用户需要编写系统分析文档时：
1. 按上述九个章节创建文档框架
2. 根据实际需求填充内容
3. 使用画板绘制架构图、流程图、ER图等
4. 按模板格式填写数据库设计和接口定义

### 文档编写原则
- **完整性**：九个章节都要有，没有内容的章节标注"无"或"暂无"
- **规范性**：严格按照模板格式，保持表格、标题层级一致
- **可读性**：使用画板辅助说明复杂逻辑
- **可维护性**：数据库设计和接口定义要详细，便于后续维护

### 画板使用场景
- 系统架构图：展示整体架构和模块关系
- 业务流程图：展示业务流转过程
- 时序图：展示系统间交互时序
- 泳道图：展示各角色职责分工
- ER图：展示数据库表结构和关系
